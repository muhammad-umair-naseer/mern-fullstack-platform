Typing practice for programmers has to look like code. A normal typing test gives you a paragraph of English, and English barely uses the keys a developer reaches for all day: curly braces, square brackets, arrows, equals signs, quotes, underscores and semicolons. You can type 80 words per minute on prose and still slow to a crawl on `items.filter((i) => i.active)`.

This guide explains why coders need their own kind of typing practice, which characters to train, and a short daily routine. It uses the code mode in [TypeDash](/games/typedash), our free multiplayer typing race, where every passage is a real line of code.

## Why prose typing tests miss what programmers type

Typing tests measure words per minute on ordinary sentences. That is useful, but code is different in three ways:

- **Symbols everywhere.** A single line of JavaScript can have more symbols than letters. Most of them sit on the top row or need Shift, which is where fingers leave the home row and lose their place.
- **Unusual word shapes.** `camelCase`, `snake_case`, `getElementById` and `__init__` do not follow the letter patterns your fingers learned on prose.
- **Precision over speed.** A typo in an email is a typo. A typo in code is a bug, a failed build or ten minutes of searching for a missing bracket.

So the goal for programmers is not a big number on a prose test. It is typing code accurately without looking down, so your attention stays on the problem you are solving.

## The characters that slow coders down

Watch yourself type a few lines of your own code and you will probably find the same trouble spots most developers have:

| Characters | Where they show up |
| --- | --- |
| `{ } [ ] ( )` | Every block, array, object and function call |
| `=> === !==` | Arrow functions and comparisons in JavaScript and TypeScript |
| `" ' ` and backticks | Strings and template literals |
| `_ -` | `snake_case` names, CSS classes, command line flags |
| `: ;` | Python blocks, object literals, statement ends |
| `< > /` | HTML, generics, closing tags, file paths |
| `$ # @ %` | Shell scripts, comments, decorators, formatting |

Practising these on their own is boring. Practising them inside real lines of code, the way they actually appear, is far more useful.

## A 15 minute typing routine for programmers

Short, daily sessions beat one long weekend session. Try this:

1. **Warm up, 3 minutes.** One prose passage in practice mode at an easy pace, to settle your hands on the home row.
2. **Code, 7 minutes.** Code mode passages against a pacer set a little below your comfortable speed. Aim for zero mistakes rather than speed. TypeDash's pacer can be set anywhere from 35 to 110 words per minute.
3. **Symbols, 3 minutes.** One or two numbers and symbols passages.
4. **One race, 2 minutes.** Finish with a live race, or the daily challenge, which gives everyone the same passage each day and counts only your first finished run.

Do it five days a week and keep the streak going. In TypeDash every day in a row adds 5 percent to the points you earn, up to 50 percent, and practice runs count towards the streak too.

## Do you have to type fast to be a programmer?

No. Programming is mostly reading, thinking and debugging, and plenty of excellent developers type at an ordinary speed. But being **comfortable** on the keyboard matters more than people admit. If you have to look for the bracket keys, part of your attention is on your hands instead of your code. The aim of typing practice for programmers is not to win races, it is to make typing invisible.

### What is the best typing practice for programmers?
Practice on real code rather than prose, because code is full of symbols that ordinary typing tests never ask for. A short daily routine on real snippets, with accuracy as the first goal, works better than occasional long sessions.
