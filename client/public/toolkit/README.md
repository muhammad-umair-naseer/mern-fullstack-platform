# Cortexis Free Online Toolkit

**46 browser-based tools · 100 % client-side · zero third-party dependencies.**

Every engine in this repository — PDF parsing/writing, Deflate, PNG/JPEG/ICO/GIF codecs, ZIP/TAR/GZIP, MP4 demux/mux, XML, CSV/YAML, Markdown, DOCX/XLSX readers, EXIF, SVG optimisation, WSOLA time-stretch — was written from scratch in plain ES modules. There is no `node_modules` folder, no CDN, no web font and no network request at runtime. Files never leave the user's device.

```
index.html            hub (search, categories, ★ favourites, recently used)
tool.html             generic tool shell (tool.html?t=<slug>)
tools/<slug>/         static SEO page per tool (generated by `npm run build`)
assets/app.css        single stylesheet (light + dark)
src/registry.js       the 46 tools: slug, name, category, description, keywords
src/hub.js            hub logic
src/tool-shell.js     loads src/tools/<slug>.js and mounts it
src/core/             engines (see below)
src/tools/            one module per tool: export function mount(root, ctx)
scripts/              build-pages.mjs (static pages + sitemap), serve.mjs (dev server), check-syntax.mjs
tests/unit            node:test suites (33 tests, cross-checked against qpdf/pdftotext/ffmpeg/unzip/PIL/PyYAML when installed)
tests/browser         Playwright smoke + functional tests (93 checks: every page loads without console errors; 43 tools exercised end to end)
```

## Running locally

```bash
node scripts/serve.mjs 8080      # or: npm run serve
open http://localhost:8080/
```

No install step is needed (Node ≥ 20 for the dev server/tests; the site itself is static).

`npm run build` generates `tools/<slug>/index.html` for every tool (title, meta description, canonical URL, Open Graph, JSON-LD, related-tools footer) plus `sitemap.xml` and `robots.txt`. Pass your base URL: `node scripts/build-pages.mjs --site https://cortexis.pk`. The generated pages live under `tools/…` relative to wherever `index.html` is deployed.

## Tests

External tools are optional: when `qpdf`, `pdftotext`, `ffmpeg`, `unzip` or Python/PIL/PyYAML are present the tests use them as independent oracles (e.g. every generated PDF must pass `qpdf --check`; muted MP4s must be frame-identical under `ffmpeg -f framemd5`).

## Honest limits of a dependency-free, browser-only toolkit

These are stated inside the tools too, so users are never misled:

* **HEIC** decoding relies on the browser's own image decoder: works in Safari (macOS/iOS) and on systems with HEIF support; Chrome/Firefox on Windows/Linux cannot decode it and the tool says so per file.
* **MP3 encoding** is not offered. Writing an MP3 encoder from scratch (psychoacoustic model + Huffman tables) is out of scope and browsers have no native one; audio tools export **WAV** (universal) and **M4A/AAC** (WebCodecs) instead.
* **RAR / 7Z** cannot be unpacked without third-party code (proprietary/LZMA); the archive tool detects them, explains it and passes the files through unchanged. ZIP, TAR, TAR.GZ/TGZ and GZ are fully supported natively.
* **OCR** uses the browser's Shape Detection `TextDetector` where it exists (Chrome on Android/macOS with flags in some versions); elsewhere the tool prepares the scan (upscale, grayscale, Otsu binarisation) for the site's existing tesseract.js page or any OCR app.
* **Background removal** is a classic colour-based cutout (flood fill + feathering + manual touch-up), not a neural segmentation model. It is excellent on plain/gradient/studio backgrounds and honest about busy ones.
* **PDF previews** use the browser's built-in PDF viewer (`navigator.pdfViewerEnabled`); where absent (some mobile browsers) the Download button is offered instead.
* **Video export** needs WebCodecs for MP4 (Chrome/Edge 94+, Safari 16.4+, Firefox 130+); every video tool falls back to WebM via MediaRecorder elsewhere. Frame-exact extraction is done by seek-stepping the `<video>` element, so exports run at roughly real time to 2× real time depending on the machine.

## Browser support

Chrome/Edge 94+, Safari 16.4+, Firefox 115+ (Firefox: MP4 export via WebCodecs from 130+, WebM otherwise). Requires `DecompressionStream`/`CompressionStream` (2022+ browsers) for Deflate; a pure-JS inflate is used for reading regardless.

## Integrating into the Cortexis React site

The toolkit is intentionally framework-free so it can be embedded without a build step:

1. Copy `src/`, `assets/` and (optionally) the generated `tools/` folder into `public/` (e.g. `public/toolkit/`).
2. **Option A – iframe/route per tool:** link to `/toolkit/tools/<slug>/` (static SEO pages) or `/toolkit/tool.html?t=<slug>`.
3. **Option B – mount inside a React component:**

```jsx
import { useEffect, useRef } from 'react';
export function Tool({ slug }) {
  const ref = useRef(null);
  useEffect(() => {
    let alive = true;
    import(/* @vite-ignore */ `/toolkit/src/tools/${slug}.js`).then((m) => { if (alive && ref.current) { ref.current.replaceChildren(); (m.mount || m.default)(ref.current, { tool: { slug } }); } });
    return () => { alive = false; ref.current && ref.current.replaceChildren(); };
  }, [slug]);
  return <div ref={ref} className="tool-host" />;
}
```
   Include `<link rel="stylesheet" href="/toolkit/assets/app.css">` in `index.html` (or import it), and expose the registry with `import { TOOLS, CATEGORIES } from '/toolkit/src/registry.js'` to build your own cards/menus.
4. The existing pdf-lib / tesseract.js / ffmpegEngine pages can stay; the new tools do not depend on them.

## Security & privacy notes

* Nothing is uploaded; there are no analytics calls and no external scripts.
* Favourites/recents use `localStorage` keys `cortexis.favorites` / `cortexis.recent` only.
* The Markdown renderer neutralises `javascript:`/`data:` links; raw HTML blocks are passed through only in the HTML export (as any Markdown renderer does) — sanitise if you render untrusted input.
* Redaction removes glyphs from the page content stream and drops intersecting annotations. Text drawn inside nested form XObjects is covered rather than removed; the tool's post-check searches the whole document text and warns if the searched string still appears.
